# Stay Sync 주요 기능 소개 PPT 제작 지시서

## 1. 작업 목적

Stay Sync가 어떤 문제를 해결하며, 사용자 입력부터 관광지 추천과 최종 동선 생성까지 어떤 기능을 제공하는지 소개하는 발표 자료를 제작한다.

이 문서는 PPT 제작 에이전트가 별도의 요구사항 확인 없이 슬라이드를 만들 수 있도록 작성한 작업 지시서다. 아래에 적힌 사실을 중심으로 구성하고, 확인되지 않은 성능 수치·사용자 수·정확도·수상 실적은 임의로 추가하지 않는다.

## 2. 발표 자료 기본 조건

- 언어: 한국어
- 권장 분량: 14장 내외
- 권장 발표 시간: 7~10분
- 대상: 교수, 심사위원, 공모전 평가자 및 프로젝트 관계자
- 핵심 메시지: **Stay Sync는 사용자의 자연어를 이해하고 동행자·관심 활동·날씨·미세먼지를 함께 고려해 관광지를 추천한 뒤, 도로망 기반의 날짜별 최적 동선과 여행 이야기까지 제공하는 관광 챗봇이다.**
- 슬라이드마다 긴 문단을 넣지 말고 핵심 문구와 시각 자료를 중심으로 표현한다.
- 기능 설명에는 가능한 한 실제 입력 예시와 처리 결과를 함께 보여준다.
- 시스템에 없는 기능이나 검증되지 않은 수치를 만들어내지 않는다.

## 3. 권장 디자인 방향

- 전체 분위기: 밝고 신뢰감 있는 여행 서비스
- 주 색상: 파란색 계열
- 보조 색상: 날씨·자연을 연상시키는 하늘색과 초록색
- 배경: 흰색 또는 매우 밝은 회색
- 강조 방식: 중요한 키워드는 굵게 표시하고, 기능별 아이콘과 짧은 도식 사용
- 권장 시각 요소: 챗봇 대화창, 여행지 카드, 달력, 날씨, 미세먼지, 온톨로지 연결 구조, 지도 경로
- 한 슬라이드의 핵심 메시지는 하나로 제한한다.
- 코드 화면보다 사용자가 경험하는 흐름을 우선해서 보여준다.

## 4. 슬라이드 구성

### 슬라이드 1. 표지

**제목:** Stay Sync

**부제:** 동행자와 여행 상황을 이해하는 관광지 추천 챗봇

**하단 문구:** 자연어 여행 정보 수집부터 상황인지 추천, 동선 최적화까지

**시각 자료:** 챗봇 말풍선과 지도 경로를 결합한 대표 이미지

---

### 슬라이드 2. 프로젝트가 해결하려는 문제

**핵심 문구:** 여행자는 숙소, 관광지, 날씨, 이동 경로를 서로 다른 서비스에서 따로 확인해야 한다.

**내용:**

- 여행 조건을 여러 번 입력해야 하는 불편
- 동행자와 관심 활동이 충분히 반영되지 않는 일반적인 추천
- 날씨와 미세먼지를 고려하지 않은 고정적인 관광지 목록
- 관광지를 고른 뒤 다시 이동 순서를 직접 계획해야 하는 문제

**시각 자료:** `정보 검색 → 관광지 선택 → 날씨 확인 → 경로 작성`으로 분리된 기존 과정

---

### 슬라이드 3. Stay Sync의 전체 사용자 흐름

**핵심 문구:** 한 번의 대화가 개인화된 여행 일정으로 완성된다.

**흐름:**

`자연어 입력 → 여행 목적 분기 → 날짜·장소 해석 → 동행자·활동 테마 매핑 → 날씨·미세먼지 반영 → 관광지 추천 및 선택 → 날짜별 동선 최적화 → 카카오맵·스토리텔링 제공`

**추가 분기:**

- 숙소 추천이 필요한 사용자
- 숙소를 이미 예약한 사용자
- 방문 장소를 정하고 동선만 필요한 사용자

**시각 자료:** 가로형 단계 흐름도

---

### 슬라이드 4. 기능 1 — 자연어 기반 여행 정보 수집

**핵심 문구:** 사용자가 평소 말하듯 입력해도 필요한 여행 정보를 한 번에 추출한다.

**주요 기능:**

- 한 문장에서 지역·관광지·동행자·기간 추출 및 저장
- 이미 입력된 정보는 다시 질문하지 않음
- 여러 관광지를 한 문장으로 입력해도 모두 저장
- 실제 데이터에 지역명이나 괄호 설명이 붙어 있어도 핵심 관광지명으로 검색

**입력 예시:**

> 가족들이랑 내일부터 이틀간 동구릉이랑 자라섬에 갈 거야.

**추출 예시:**

- 동행자: 가족
- 시작일: 내일
- 기간: 2일
- 관광지: 동구릉, 자라섬
- 지역: 구리, 가평

**데이터 검색 예시:** `구리 동구릉 [유네스코 세계유산]`을 사용자가 `동구릉`이라고만 말해도 검색

---

### 슬라이드 5. 기능 2 — 사용자 목적별 맞춤 대화

**핵심 문구:** 사용자의 준비 상태에 따라 필요한 질문만 한다.

**세 가지 대화 경로:**

1. 숙소 추천이 필요한 사용자
2. 숙소를 이미 예약한 사용자
3. 관광지를 정했고 동선만 추천받으려는 사용자

**처리 방식:**

- 숙소 예약 완료 사용자는 숙소 추천 단계를 생략
- 당일치기 사용자는 숙소 대신 출발지를 입력
- 동선 전용 사용자는 방문 관광지와 여행 일수를 받아 자동 배분

**시각 자료:** 세 갈래 분기 후 최종 동선 단계에서 다시 합쳐지는 구조

---

### 슬라이드 6. 기능 3 — 공휴일·상대 표현을 포함한 날짜 해석

**핵심 문구:** 일상적인 날짜 표현을 실제 여행 날짜로 변환한다.

**지원 예시:**

- `개천절 연휴`
- `내일부터 이틀간`
- `6월 5일부터 7일까지`
- 연도를 생략한 날짜

**처리 규칙:**

- 상대 날짜와 기간 표현을 시작일·종료일로 변환
- 음력 공휴일과 대체공휴일을 연도별로 계산
- 연도를 말하지 않은 날짜가 이미 지났다면 다음 해로 해석

**시각 자료:** 자연어 문장이 달력의 날짜 범위로 변환되는 모습

---

### 슬라이드 7. 기능 4 — 정정 의사 감지와 대화 복구

**핵심 문구:** 잘못 입력하거나 처리 오류가 발생해도 여행 정보가 끊기지 않는다.

**주요 기능:**

- `아니다`, `말고`, `잘못 선택했어` 등의 정정 의사 감지
- 직전 단계로 돌아가 다시 선택 가능
- 사용자가 직접 방문 의사를 밝힌 목적지는 보존
- 처리 중 오류가 발생하면 오류 화면에서 멈추지 않고 기존 질문을 다시 제시

**시각 자료:** `관광지 선택 → 정정 감지 → 직전 선택 복구` 대화 예시

---

### 슬라이드 8. 기능 5 — 동행자·관심 활동 온톨로지 기반 테마 추천

**핵심 문구:** 누구와 무엇을 하고 싶은지에 따라 추천 테마가 달라진다.

**동행자 예시:**

- 혼자
- 연인
- 친구
- 가족
- 부모님
- 아이 동반

**관심 활동 예시:**

- 빠지
- 글램핑
- 온천

**처리 방식:** 동행자 유형과 관심 활동을 관광 테마에 연결하고, 두 조건을 관광지 추천 필터에 반영한다.

**시각 자료:** `동행자 + 활동 → 관광 테마 → 관광지` 온톨로지 연결 구조

---

### 슬라이드 9. 기능 6 — 숙소 검색과 장소 자동완성

**핵심 문구:** 일정과 지역에 맞는 장소를 정확한 좌표로 연결한다.

**주요 기능:**

- 지역과 체크인·체크아웃 날짜가 적용된 야놀자 숙소 검색 링크 제공
- 당일치기 여행에는 숙소 링크를 제공하지 않음
- 관광지·숙소·출발지 검색 및 자동완성
- 사용자가 후보를 선택하면 장소명과 좌표 저장
- 숙소 검색 시 여행 지역에 해당하는 결과를 우선 제시

**시각 자료:** 숙소 검색 링크와 자동완성 목록이 포함된 챗봇 화면

---

### 슬라이드 10. 기능 7 — 날씨·미세먼지 기반 상황인지 추천

**핵심 문구:** 같은 여행이라도 방문일의 환경에 따라 추천 결과를 조정한다.

**활용 데이터:**

- 기상청 날씨 데이터
- 에어코리아 미세먼지 데이터

**처리 방식:**

- 여행 날짜의 날씨와 대기질 확인
- 비·눈·폭염·한파·미세먼지 상황을 고려
- 상황에 따라 실내·실외 관광지 추천 조건 조정
- 추천 전에 반영된 날씨·대기질과 동행자 조건을 사용자에게 안내

**시각 자료:** `날씨 + 미세먼지 + 동행자 → 실내·실외 필터` 도식

---

### 슬라이드 11. 기능 8 — 인기순·거리순 추천과 관광지 선택 관리

**핵심 문구:** 인기와 실제 이동 거리를 함께 고려하고, 원하는 관광지만 간편하게 고른다.

**추천 방식:**

- 검색순 데이터를 기반으로 인기순 관광지 추천
- 숙박 여행은 숙소 기준 도로망 거리순 관광지도 함께 추천
- 추가 추천 시 다음 순위 구간을 이어서 제공
- 이미 추천하거나 선택한 관광지는 중복 제외

**선택 기능:**

- 관광지 카드에서 사진·설명·주소·테마 확인
- 카드를 클릭해 여러 관광지 선택
- 선택 완료, 추가 추천, 선택 취소 지원

**시각 자료:** `인기순`과 `거리순` 라벨이 있는 관광지 카드 UI

---

### 슬라이드 12. 기능 9 — 날짜별 동선 최적화와 스토리텔링

**핵심 문구:** 선택된 관광지를 실제로 이동 가능한 여행 일정으로 바꾼다.

**주요 기능:**

- 처음 방문하겠다고 말한 관광지와 이후 선택한 관광지를 모두 반영
- 여행 일수에 맞춰 관광지를 날짜별로 배분
- 도로망 거리를 기반으로 방문 순서 최적화
- 구간별 거리와 총 이동 거리 제공
- 숙박 여행은 마지막 날을 제외하고 숙소 복귀 경로 반영
- 날짜별 카카오맵 길찾기 링크 제공
- 최종 일정에 자연스러운 여행 스토리텔링 추가

**시각 자료:** `출발지/숙소 → 관광지 A → 관광지 B → 숙소` 지도 경로

---

### 슬라이드 13. 기능 10 — 언어 감지 기반 한국어·영어 대화

**핵심 문구:** 입력 언어를 감지해 한국어와 영어 여행 대화를 지원한다.

**주요 기능:**

- 입력 문자를 기반으로 언어 판별
- 번역을 전제로 하지 않고 각 언어 입력을 그대로 해석
- 응답 문구를 언어별 카탈로그로 분리
- 영어 대화에서는 영문명이 확보된 관광지만 추천
- 영문 관광 정보가 없는 지역은 추천 전에 안내

**시각 자료:** 같은 여행 요청을 한국어와 영어로 입력하는 두 개의 대화창

---

### 슬라이드 14. 차별점 및 마무리

**제목:** 검색을 넘어, 여행의 맥락과 이동까지 연결합니다

**핵심 차별점:**

- 자유로운 자연어에서 여행 조건을 한 번에 수집
- 동행자·활동·날씨·미세먼지를 결합한 상황인지 추천
- 관광지 추천부터 도로망 기반 동선과 카카오맵 연결까지 하나의 대화에서 완료
- 입력 정정과 오류 복구를 지원해 끊기지 않는 사용자 경험 제공
- 한국어·영어 사용자에 맞춘 관광 데이터 제공

**마무리 문구:**

> Stay Sync는 관광지를 나열하는 챗봇이 아니라, 사용자의 상황을 이해하고 실제 여행 가능한 일정으로 완성하는 동행자 맞춤 여행 서비스입니다.

## 5. PPT 제작 시 지켜야 할 표현

- `검색순`은 데이터에 저장된 관광지 검색 순위를 의미하므로 임의로 `실시간 인기순`이라고 표현하지 않는다.
- 거리순과 동선 계산은 직선거리가 아니라 도로망 거리 기반이라는 점을 명시한다.
- 날씨와 미세먼지는 관광지를 무조건 제거한다고 단정하지 말고, 실내·실외 추천 조건을 조정한다고 표현한다.
- 다국어 지원은 현재 한국어·영어를 중심으로 설명한다.
- 숙박 여행의 복귀 규칙은 마지막 날을 제외한 날짜에 숙소로 복귀하는 방식으로 표현한다.
- 사용자가 처음부터 방문하겠다고 밝힌 관광지도 최종 동선에 포함된다고 설명한다.
- 카카오맵에는 파일을 내려받는 방식이 아니라 길찾기 링크로 연결된다고 표현한다.

## 6. 제작 에이전트에게 전달할 실행 프롬프트

아래 문장을 이 파일과 함께 PPT 제작 에이전트에게 전달한다.

> 첨부된 `stay-sync-ppt-brief.md`의 사실과 슬라이드 구성을 기준으로 한국어 발표 자료를 제작해줘. 14장 내외, 발표 시간 7~10분 분량으로 구성하고, 밝고 신뢰감 있는 여행 서비스 디자인을 사용해줘. 각 장에는 하나의 핵심 메시지만 배치하고 긴 문단 대신 짧은 문구, 아이콘, 챗봇 대화 예시, 흐름도, 관광지 카드, 지도 경로 등 시각 자료를 활용해줘. 문서에 없는 성능 수치나 실적은 만들지 말고, 기능 설명의 정확성을 우선해줘. 결과물은 편집 가능한 PPTX로 제공하고 모든 슬라이드의 글자가 잘리지 않는지 확인해줘.
